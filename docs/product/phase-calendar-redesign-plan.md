# 日程页产品级重设计方案

## 1. 当前审计结论

当前日程页已经通过正式 API 读取 PostgreSQL 中的 `CalendarEvent`、`TeacherTodo` 和 `TeacherWorkProjection`，并具备创建、编辑、完成、重新打开、安排到日历和来源业务跳转能力。问题主要不是“没有后端”，而是前端没有把这些能力组织成教师熟悉的工作方式：

- 日视图以整点行包裹事件，无法表达事件时长、重叠与全天事项；
- 周视图只是七列事件列表，没有共享时间轴；
- 月视图缺少事件颜色、溢出数量和日期选择反馈；
- 日程类型只有文字标签，没有跨视图一致的视觉语言；
- 创建弹窗沿用通用表单样式，标题、日期时间和错误反馈层级不清；
- 待办把个人待办、取消、稍后提醒和业务投影拆成五个标签，教师需要理解内部模型；
- 页面字号、热区、圆角和留白偏小，侧边栏分割线与三点图标增加了视觉噪声；
- Sample Seed 没有提供围绕当前日期的一天、一周和一月日程，因此真实页面经常显得空。

## 2. 视觉系统

本次沿用 Edu-Agent 蓝色主色，不复制 Gemini 或 Apple 品牌元素，只采用其信息密度和空间组织原则。

| 层级 | 方案 |
|---|---|
| 页面背景 | `#F6F8FC`，内容卡片使用白色 |
| 主要圆角 | 页面卡片 24px，弹窗 24px，菜单项 16px，事件块 10–12px |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32px 八点栅格 |
| 页面标题 | 30px / 700 |
| 模块标题 | 20px / 650 |
| 正文 | 15px / 400–500 |
| 辅助文字 | 12–13px，使用二级或弱化文字色 |
| 侧边栏图标 | 22px，统一 1.8px 线宽 |
| 菜单热区 | 最低 52px，高亮使用浅蓝底而非分割线 |

侧边栏移除教师姓名右侧三点，教师头像区域本身继续作为工作空间菜单入口；减少顶部和底部硬分割线，以留白表达层级。

## 3. 日 / 周 / 月视图

### 日视图

- 采用 06:00–22:00 的共享时间轴；
- 事件按开始分钟和持续时间绝对定位，最短高度保证可读；
- 全天事项单独置于时间网格上方；
- 当前日期为今天时显示当前时间线；
- 事件块展示标题、时间和类别，颜色由类别固定映射。

### 周视图

- 顶部为星期和日期，今天使用蓝色圆形日期标记；
- 左侧共享时间轴，七天使用同一网格；
- 事件按真实开始时间和时长放置，而不是逐日列表；
- 全天事项使用顶部紧凑条带。

### 月视图

- 固定六周网格，当前月与相邻月清楚区分；
- 每个日期最多显示三条彩色事件，超出显示“还有 N 项”；
- 点击日期切换到对应日视图；
- 事件颜色与日、周视图完全一致。

事件分类使用正式 `CalendarEventType` 与来源投影共同推导，不在前端复制业务状态。上课、会议、备课、批改、个人提醒、待办时间块和作业截止均有固定颜色；巡班/值班与学校事务作为个人日程的明确类别写入正式事件类型，而非通过标题关键词猜测。

## 4. 新建日程

- 标题统一为“新建日程”或“编辑日程”；
- 字段为标题、说明、类型、开始、结束、全天；
- 两列日期时间布局在窄屏自动降为单列；
- 结束时间必须晚于开始时间，错误在弹窗内直接说明；
- 去除内部实现说明和英文取消文案；
- 来源业务日程保持只读并继续跳转源页面。

本轮不引入地点字段，避免在没有持久化字段的情况下把地点塞进说明。若后续需要地点，将通过独立前向 Migration 和 Contract 扩展实现。

## 5. 统一待办与统计

主界面只保留“进行中 / 已完成”两个状态：

- 个人待办以圆形 checklist 展示，可直接完成或重新打开；
- 系统业务提醒并入“进行中”，但保留来源标识和“去处理”动作，不能在工作台伪造源业务完成；
- 取消和稍后提醒能力仍由后端保留，但不占据主标签；
- 编辑、安排日历、关联课时与 Agent 入口收纳到行内次要操作，默认不压过待办标题。

统计模块使用同一批正式日历数据，支持今日 / 本周 / 本月切换。以轻量环形图和分类时长列表展示时间分布，不建立新的统计真值表。

## 6. 林老师 Sample Seed

Sample 数据继续只存在于 `scripts/sample` 和 `packages/sample-data`，不进入正式 API 运行时依赖。`pnpm sample:seed` 将围绕执行当天生成可重复、可审计的林老师工作月数据：

- 工作日课程、晨会、备课、批改、会议、巡班和个人提醒；
- 当前周的重点安排与全天学校事务；
- 进行中、已完成、系统来源和个人来源待办；
- 所有数据写入 PostgreSQL，页面仍只通过正式 API 读取；
- 使用日期化幂等键，重复 Seed 不产生同日重复数据。

## 7. 边界与验证

- 不改变 TeachingPlan、Assignment、Evidence、Agent 或身份状态语义；
- 来源业务投影不能被本地 checkbox 直接完成；
- 不修改历史 Migration；如扩展正式日程类别，仅新增 Work 模块前向 Migration；
- 保持日 / 周 / 月视图使用同一个 Calendar API；
- 覆盖类型检查、单元测试、架构测试、PostgreSQL、Playwright、Fake Ark 与生产构建；
- 浏览器验收重点检查日/周/月、创建日程、完成待办、统计切换和刷新恢复。
